# Как база лодок попадает на сайт

Правило: **база живёт здесь, сайт её не хранит и не редактирует.**

```
yachts.csv  ──generate.py──►  (140 лодок из исходной таблицы)
                                      │
                                      ├── build-fleet.py
                                      ▼
                                 fleet.csv  ◄── БАЗА. Её и правим.
                                      │            170 лодок, 45 регионов
                                      │
      ┌───────────────────────────────┴───────────────┐
      ▼                                               ▼
  npm run fetch-photos                          npm run sync-fleet
  качает кадры в public/fleet/              пишет src/data/fleet.data.ts
      │                                               │
      └───────────────► сайт собирается ◄─────────────┘
                     и больше ни от чего не зависит
```

## Обновить каталог

1. Правим `fleet.csv` — это единственный файл с данными.
2. `npm run fetch-photos` — если появились новые ссылки на кадры.
3. `npm run sync-fleet` — переносит базу в сборку.

Шаг 3 вызывается автоматически перед `npm run dev` и `npm run build`,
так что вручную его запускать обычно не нужно.

## Пересобрать базу с нуля

Порядок важен: `build-fleet.py` перезаписывает файл целиком, поэтому
переназначение фотографий идёт следом.

```bash
python3 build-fleet.py    # yachts.csv + собственные лодки → fleet.csv
python3 fix-photos.py     # выкидывает отбракованные кадры
npm run sync-fleet        # из папки сайта
```

## Почему не читаем CSV прямо из сайта

Так было в первой версии, и это ломалось при публикации: на сервере
файла `../../data/fleet.csv` попросту нет. Сейчас данные переносятся
в модуль `src/data/fleet.data.ts` и уезжают вместе со сборкой —
опубликованный сайт работает, даже когда компьютер с базой выключен.

Проверено: если убрать `fleet.csv`, `npm run build` всё равно проходит
на ранее синхронизированных данных.

## Почему кадры скачиваем

В базе стоят ссылки на Викисклад и Тильду. Викисклад отвечает
`429 Too Many Requests` уже при локальной разработке, а чужой файл может
исчезнуть в любой момент. `fetch-photos` кладёт 38 кадров в `public/fleet/`
под именами-хешами от ссылки, `sync-fleet` подменяет ссылки на локальные пути.

Если кадр не скачался, он останется внешней ссылкой, и `sync-fleet`
предупредит об этом в консоли.

## Схема

К колонкам исходной таблицы добавлена одна — **«Тип лодки»**
(`Спортивная` / `Круизная` / `Моторная`). Без неё не выразить правило
«спортивная берётся только на день и только с базы «Силы ветра»».

Проверки, которые не дадут собрать битую базу:

- повар доступен только от 12 метров;
- у спортивной лодки не бывает кают;
- на спортивную лодку помещается не больше пяти гостей;
- названия уникальны — из них строятся адреса страниц.

Повар — не услуга в стоимости, а галка при бронировании: она появляется
только у лодок с признаком «Добавить повара» и прибавляет 8 000 ₽ к суткам.

## Фотографии каталога

Все 38 скачанных кадров отсмотрены глазами. Отбраковано 22: надувные
катамараны и тримараны, байдарки с парусом, разборные микро-лодки, баржа,
портовые краны, здание яхт-клуба, пустая набережная и моторные яхты.
Остались 16 кадров с настоящими парусными яхтами, они раздаются по кругу —
повторы допустимы.

Списки «годных» и «отбракованных» лежат в `fix-photos.py`. Скрипт проверяет,
что каждая одобренная ссылка есть в манифесте: опечатка в хеш-префиксе
Викисклада даёт живую с виду ссылку, которая молча осталась бы внешней.
